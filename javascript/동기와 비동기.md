# 동기(Synchronous) vs 비동기(Asynchronous)

> 2026-05-13 (Wed)

## ✨ What I Learned

- **동기(Synchronous)** : 작업을 순서대로 하나씩 처리하는 방식
  - 앞 작업이 완전히 끝나야 다음 작업 시작
  - JS의 기본 실행 방식
  - 단점 : 오래 걸리는 작업 하나가 전체 프로그램을 block

- **비동기(Asynchronous)** : 앞 작업이 끝나길 기다리지 않고 다음 작업을 바로 시작하는 방식
  - Single thread인 JS가 동시 처리를 할 수 있는 핵심 메커니즘

- **JS가 Single Thread인데 어떻게 비동기가 가능한가?**
  - JS 엔진(Call Stack)은 thread 1개 → 멀티 스레드 불가
  - 비동기 작업(`setTimeout`, `fetch` 등)은 **Web APIs**가 대신 처리
  - 완료된 콜백은 **Task Queue**에 대기 → **Event Loop**가 Call Stack이 비면 꺼내서 실행

## 💠 Example / Code

```javascript
console.log("1");

setTimeout(() => {
  console.log("2"); // 3초 후 Web API → Task Queue → Event Loop → 실행
}, 3000);

console.log("3");

// 출력 순서: 1 → 3 → 2
// setTimeout은 비동기이므로 "3"이 먼저 출력된 뒤 3초 후 "2" 출력
```

## ✒️ Usage

- 서버 API 호출(`fetch`, `axios`) 시 응답을 기다리는 동안 다른 코드를 실행해야 할 때
- 파일 읽기/쓰기, DB 쿼리 등 I/O 작업의 완료를 기다릴 때 (`fs.readFile`, `await query(...)`)
- `setTimeout` / `setInterval`로 특정 시간 이후 또는 주기적으로 작업을 예약할 때
- 사용자 이벤트(클릭, 입력 등) 처리 시 — 이벤트 리스너 자체가 비동기 콜백 기반
